# 01. Git이란 무엇인가

## 한 줄 요약

> **Git = 파일의 변경 이력을 저장하고, 여러 사람이 동시에 작업한 결과를 안전하게 합쳐주는 도구**

## 1. "버전 관리"가 왜 필요한가

이런 경험, 한 번쯤 있으시죠?

```
보고서_최종.docx
보고서_최종_v2.docx
보고서_진짜최종.docx
보고서_진짜최종_이번엔진짜.docx
```

이게 바로 **버전 관리(Version Control)를 손으로 하는 모습**입니다. 문제가 많죠.

- 어떤 게 최신인지 헷갈린다
- 누가 무엇을 바꿨는지 모른다
- 이틀 전 상태로 되돌리고 싶은데 방법이 없다
- 두 사람이 각자 고친 걸 합치다가 실수로 덮어쓴다

**Git은 이 모든 걸 자동으로, 안전하게 해줍니다.**

- 모든 변경이 **스냅샷(commit)** 으로 기록되어 언제든 과거로 돌아갈 수 있다
- **누가 / 언제 / 왜** 바꿨는지 전부 남는다
- 여러 사람의 작업을 **충돌 없이(혹은 충돌을 알려주며)** 합쳐준다

## 2. 핵심 개념 4가지

처음엔 이 4개만 이해하면 됩니다.

| 개념 | 한 줄 설명 | 비유 |
|------|-----------|------|
| **Repository (저장소, repo)** | 프로젝트 전체 + 모든 변경 이력이 담긴 폴더 | 프로젝트 상자 |
| **Commit (커밋)** | 특정 시점의 스냅샷 (변경의 저장 단위) | 게임 세이브 포인트 |
| **Branch (브랜치)** | 독립적으로 작업하는 평행 작업선 | 평행우주 |
| **Remote (원격)** | 인터넷(GitHub)에 있는 공유 저장소 | 팀 공용 클라우드 |

### 비유로 이해하기

- **Commit**은 게임의 **세이브 포인트**입니다. 망쳐도 세이브 지점으로 돌아가면 됩니다.
- **Branch**는 **평행우주**입니다. 본편(main)을 건드리지 않고 "내 우주"에서 마음껏 실험하다가,
  성공하면 본편에 합칩니다(merge/rebase).
- **Remote(GitHub)**는 팀이 함께 보는 **공용 클라우드**입니다. 내 컴퓨터(로컬)에서 작업하고
  `push`로 올리고, 남의 작업을 `pull`로 받아옵니다.

## 3. Git vs GitHub — 헷갈리지 마세요

자주 헷갈리는 부분입니다.

| | Git | GitHub |
|---|-----|--------|
| 정체 | **도구(프로그램)** | **웹 서비스(사이트)** |
| 역할 | 내 컴퓨터에서 버전 관리 | Git 저장소를 인터넷에 호스팅 + 협업 기능 |
| 비유 | 카메라 | 인스타그램 |

- **Git** 없이도 혼자 버전 관리는 가능합니다.
- **GitHub**는 그 저장소를 팀과 공유하고, PR 리뷰·이슈·권한 관리 같은 **협업 기능**을 더해줍니다.
- GitHub 외에 GitLab, Bitbucket 등도 같은 역할을 합니다. **우리 팀은 GitHub를 사용합니다.**

## 4. 전체 그림: 로컬 ↔ 원격

```
   내 컴퓨터 (로컬)                          GitHub (원격)
 ┌─────────────────────┐                  ┌──────────────────┐
 │  작업 폴더            │                  │                  │
 │   (파일 수정)         │                  │   공유 저장소      │
 │      │ git add       │                  │   (origin)       │
 │      ▼               │   git push  ───▶ │                  │
 │  Staging (준비 영역)  │                  │                  │
 │      │ git commit    │   git pull  ◀─── │                  │
 │      ▼               │                  │                  │
 │  로컬 저장소(이력)     │                  │                  │
 └─────────────────────┘                  └──────────────────┘
```

이 흐름(작업 → add → commit → push / pull)이 Git 사용의 90%입니다.
다음 문서에서 설치부터 직접 해봅니다.

## 5. 자주 나오는 오해

- ❌ "Git은 백업 도구다" → 백업도 되지만, 핵심은 **이력 관리 + 협업**입니다.
- ❌ "커밋하면 GitHub에 올라간다" → 아닙니다. 커밋은 **내 컴퓨터에만** 저장됩니다.
  GitHub에 올리려면 별도로 `push` 해야 합니다.
- ❌ "Git을 잘못 쓰면 작업이 날아간다" → 한 번 커밋한 것은 웬만해선 사라지지 않습니다.
  Git은 오히려 **실수를 되돌리기 위한** 도구입니다.
