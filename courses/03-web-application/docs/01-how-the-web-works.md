# 01. 웹은 어떻게 동작하는가 — 요청과 응답

## 한 줄 요약

> **웹 = 브라우저(클라이언트)가 "주소로 요청을 보내고", 서버가 "결과를 응답하는" 일의 반복.**
> 우리가 주소창에 주소를 치는 순간, 이 요청/응답이 시작됩니다.

## 1. 등장인물 둘 — 브라우저와 서버

웹에는 딱 두 명의 주인공이 있습니다.

| 등장인물 | 다른 이름 | 하는 일 |
|----------|-----------|---------|
| **브라우저** | 클라이언트(Client) | 주소(URL)로 **요청**을 보내고, 받은 결과를 화면에 **그림** 🎨 |
| **서버** | Server | 요청을 받아 알맞은 데이터(HTML·JSON 등)를 **돌려줌** 📦 |

비유하자면 **식당 주문**과 같습니다.

- **브라우저** = 손님: "비빔밥 하나 주세요"라고 **주문(요청)** 합니다.
- **서버** = 주방: 주문을 받아 음식을 만들어 **내어줍니다(응답)**.

> 💡 "서버"는 거창한 게 아닙니다. **요청을 받아 응답을 돌려주는 프로그램**이면 모두 서버입니다.
> 다음 강좌(05-web-server-python)에서는 여러분의 노트북에서 직접 작은 서버를 띄워봅니다.

## 2. URL — 인터넷의 주소

브라우저가 요청을 보내려면 **어디로** 보낼지 알아야 합니다. 그 주소가 **URL**입니다.

```
https://example.com:443/api/messages?page=2
└─┬─┘   └────┬────┘ └┬┘ └─────┬─────┘ └──┬──┘
프로토콜    호스트   포트     경로        쿼리
(약속)    (어느 컴퓨터) (문)  (무엇을)   (추가 조건)
```

| 부분 | 의미 | 예 |
|------|------|----|
| **프로토콜** | 통신 약속(규칙) | `https://` |
| **호스트(도메인)** | 어느 컴퓨터(서버)인가 | `example.com` |
| **포트** | 그 컴퓨터의 몇 번 문인가 | `:443`, `:8000` |
| **경로(path)** | 그 안에서 무엇을 원하나 | `/api/messages` |
| **쿼리(query)** | 추가 조건 | `?page=2` |

> 💡 우리가 만들 서버는 보통 `http://localhost:8000` 에서 동작합니다. `localhost` 는
> **"내 컴퓨터 자신"** 을 가리키는 특별한 주소입니다.

## 3. HTTP — 요청과 응답의 언어

브라우저와 서버가 대화할 때 쓰는 **약속(프로토콜)** 이 바로 **HTTP**입니다.
모든 대화는 **요청(Request) → 응답(Response)** 한 쌍으로 이뤄집니다.

```
[브라우저]  ── HTTP 요청(Request)  ──▶  [서버]
[브라우저]  ◀── HTTP 응답(Response) ──   [서버]
```

**요청**에는 보통 이런 정보가 담깁니다.

- **메서드(Method)**: 무엇을 하려는가 — `GET`(가져오기), `POST`(보내기) 등
- **URL**: 어디로
- **헤더(Header)**: 부가 정보 (어떤 형식을 원하는지 등)
- **본문(Body)**: 보낼 데이터 (POST일 때 주로 사용)

**응답**에는 이런 정보가 담깁니다.

- **상태 코드(Status Code)**: 결과가 어땠는가 — `200`(성공), `404`(없음), `500`(서버 오류)
- **본문(Body)**: 실제 데이터 (HTML 문서, 또는 JSON 같은 데이터)

> 📖 메서드·상태코드·JSON은 다음 강좌 [05-web-server-python](../../05-web-server-python/README.md)에서 더 깊게 다룹니다.
> 지금은 "묻고(요청) 답한다(응답)" 라는 큰 그림만 잡으면 충분합니다.

## 4. 주소창에 주소를 치면 무슨 일이 일어날까?

`https://example.com` 을 치고 Enter를 누르는 순간, 대략 이런 일이 순서대로 벌어집니다.

1. 🔎 **주소 해석(DNS)**: `example.com` 이라는 이름을 실제 컴퓨터 주소(IP)로 변환합니다.
   (사람 이름 → 전화번호를 찾는 전화번호부 같은 역할)
2. 📨 **요청 전송**: 브라우저가 그 서버로 `GET /` HTTP 요청을 보냅니다.
3. 🛠️ **서버 처리**: 서버가 요청을 받아 알맞은 **HTML 문서**를 만들어 응답으로 돌려줍니다.
4. 🎨 **렌더링**: 브라우저가 받은 HTML을 해석하고, 거기 연결된 **CSS·JavaScript·이미지**를
   추가로 요청해서, 최종 화면을 조립해 보여줍니다.

> 💡 즉, 화면 하나를 그리려고 **여러 번의 요청/응답**이 오갑니다. HTML 한 번, CSS 한 번,
> 이미지마다 한 번씩… 이 모든 게 HTTP 요청/응답입니다.

## 5. 웹 페이지를 이루는 3종 세트

브라우저가 받아서 조립하는 재료는 세 가지 언어로 되어 있습니다. 집 짓기에 비유하면:

| 언어 | 역할 | 비유 | 이 강의 문서 |
|------|------|------|--------------|
| **HTML** | 구조·내용 | 집의 **뼈대** 🦴 | [02. HTML 기초](02-html-basics.md) |
| **CSS** | 모양·색·배치 | **인테리어** 🛋️ | [03. CSS 기초](03-css-basics.md) |
| **JavaScript** | 동작·상호작용 | **전기·움직이는 것** ⚡ | [04. JavaScript 기초](04-javascript-basics.md) |

```html
<h1>💡 LED 제어판</h1>        <!-- HTML: 내용과 구조 -->
<button id="on">켜기</button>
```

- **HTML만** 있으면: 글자와 버튼은 보이지만 밋밋하고, 버튼을 눌러도 아무 일이 없습니다.
- **CSS를 더하면**: 색·여백·배치가 생겨 보기 좋아집니다.
- **JavaScript를 더하면**: 버튼을 눌렀을 때 실제로 동작이 일어납니다.

이 셋을 차례대로 배운 뒤 [`exercises/01`](../exercises/01-led-panel.md)에서 직접
LED 제어판을 만들어 봅니다.

## 6. 🧪 직접 해보기 — 개발자 도구로 요청/응답 엿보기

말로만 들으면 와닿지 않습니다. 직접 눈으로 요청/응답을 확인해 봅시다. (크롬 권장)

1. 아무 웹사이트나 엽니다. (예: `https://example.com`)
2. 키보드 **F12** 를 누릅니다. (또는 마우스 우클릭 → **검사**) → **개발자 도구**가 열립니다.
3. 상단 탭에서 **Network(네트워크)** 탭을 클릭합니다.
4. 그 상태에서 키보드 **F5**(새로고침)를 누릅니다.
5. 표가 주르륵 채워집니다. **하나하나가 요청/응답 한 쌍**입니다!

표에서 이런 것들을 확인해 보세요.

| 열(Column) | 무엇을 보여주나 |
|------------|-----------------|
| **Name** | 요청한 파일/주소 (HTML, CSS, 이미지 등) |
| **Status** | 응답 상태 코드 (`200` 이면 성공 ✅) |
| **Type** | 받은 자료의 종류 (document, stylesheet, script, png …) |
| **Time** | 응답까지 걸린 시간 |

> 🧪 표에서 항목 하나를 **클릭**하면, 오른쪽에 그 요청의 **헤더(Headers)**, 보낸 데이터,
> 받은 **응답(Response)** 본문까지 전부 볼 수 있습니다. "브라우저가 서버와 이렇게 대화하는구나"
> 를 눈으로 확인해 보세요. 05 강좌에서 만들 서버도 여기 그대로 나타납니다.

> ⚠️ 처음엔 항목이 수십 개라 복잡해 보일 수 있어요. 맨 위 **document** 타입(보통 HTML 문서)
> 하나만 클릭해서 살펴봐도 충분합니다.
