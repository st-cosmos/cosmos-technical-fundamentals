# 01. AI 로 개발한다는 것 — 에이전트 코딩 입문 🤖

## 한 줄 요약

> 이제는 코드를 **한 줄씩 직접 타이핑**하는 대신, **"무엇을 원하는지"를 말로 설명하면 AI 가 초안을 만들어** 줍니다.
> 그리고 그 결과를 **사람이 읽고 검증·수정**합니다. 이 흐름을 **에이전트 코딩(agentic coding)** 이라고 합니다.

## 에이전트 코딩이란?

옛날 방식은 사람이 키보드로 코드를 전부 적었습니다. 에이전트 코딩은 다릅니다.

```
[사람] 자연어로 요청  →  [AI 에이전트] 코드 생성·파일 수정·명령 실행
        ▲                                   │
        └──────  검토 / 수정 / 피드백  ◀──────┘
```

핵심은 **"한 번에 끝"이 아니라 반복**이라는 점입니다. 요청 → 결과 확인 → "여기 이렇게 고쳐줘" → 다시 확인… 이 **대화의
반복**으로 완성에 가까워집니다.

> 💡 AI "에이전트"는 단순히 문장을 답하는 챗봇을 넘어, **파일을 직접 만들고 고치고, 터미널 명령을 실행하고, 결과를
> 확인**하는 데까지 스스로 합니다. 그래서 "도우미"보다 "조수"에 가깝습니다. 하지만 **방향을 정하고 책임지는 건 여전히
> 사람**입니다. 이 강좌에서 쓰는 **Codex CLI** 가 바로 이런 에이전트입니다.

## 무엇이 달라지나

| 예전 방식 | AI 에이전트와 함께 |
|-----------|--------------------|
| 한 줄씩 직접 타이핑 | **무엇을 원하는지** 설명하면 초안을 생성 |
| 문법·API 를 검색해서 찾기 | 맥락을 주면 코드·설명을 바로 제안 |
| 막히면 오래 헤맴 | 에러 메시지를 그대로 붙여 물어보면 원인 추정 |
| 모든 걸 내가 검증 | 여전히 **내가 읽고 검증** (이건 그대로!) |

> AI 는 **"더 빨리 가는 도구"** 이지, **"생각을 대신해 주는 것"** 은 아닙니다.
> 무엇을 만들지, 결과가 맞는지 판단하는 일은 **사람의 몫**입니다.

## AI 에게 일을 잘 시키는 5가지 요령 🎯

좋은 결과는 **좋은 요청**에서 나옵니다. 다음 다섯 가지를 기억하세요.

1. **목표를 구체적으로** — 무엇을, 어디에, 어떻게 동작하길 원하는지 분명히.
2. **맥락을 주기** — 어떤 파일·기술·프레임워크를 쓰는지, 제약(버전·스타일)이 무엇인지. (Codex 에서는 `AGENTS.md` 가 이 역할 — [03](03-working-with-codex.md))
3. **작게 쪼개기** — 한 번에 거대한 기능 ❌. **작은 단계로 나눠** 하나씩 시키기.
4. **결과를 검증** — 생성된 코드를 **직접 읽고 실행**해 정말 동작하는지 확인.
5. **틀리면 피드백** — "안 돼요" ❌ → **무엇이 어떻게 잘못됐는지** 구체적으로 되돌려주기.

> 💡 한마디로 **"명확한 요청 → 확인 → 수정"의 반복** 입니다. 사람이 좋은 동료에게 일을 부탁하는 방식과 똑같습니다.

## 좋은 프롬프트 vs 나쁜 프롬프트 ✏️

### 나쁜 예 ❌

```
로그인 만들어줘
```

→ 어떤 화면? 무슨 기술? 어디에 저장? 정보가 없어 AI 가 멋대로 가정합니다.

### 좋은 예 ✅

```
지금 순수 HTML/CSS/JS 프로젝트야. (index.html 하나 사용 중)
이름 입력칸과 "켜기"/"끄기" 버튼이 있는 간단한 "LED 제어판"을 만들어줘.
- 켜기를 누르면 동그란 표시등이 노란색, 끄기를 누르면 회색으로 바뀐다
- 이름을 넣고 누르면 아래 목록에 "[시각] OO 님이 LED를 켰습니다" 를 최신순으로 쌓는다
- 서버 연동은 아직 필요 없고, 시각은 new Date() 로 만든다
- 파일은 index.html, style.css, script.js 세 개로 나눠줘
```

→ **기술·위치·동작·범위·산출물**이 분명하니 원하는 결과에 훨씬 가깝게 나옵니다.

> 💡 막막하면 이 틀을 채워 보세요:
> **"[상황/기술]에서 [무엇을] 만들어줘. [이렇게 동작]하고, [이런 제약]이 있어. [어디에] 저장해줘."**

## 한계와 검증 책임 ⚠️

AI 는 강력하지만 **완벽하지 않습니다.** 다음을 항상 기억하세요.

- **그럴듯한 거짓**(환각, hallucination): 존재하지 않는 함수·라이브러리를 자신 있게 지어낼 수 있습니다. → **실제로 실행/빌드해서 확인**하세요.
- **오래된 정보**: AI 가 알고 있는 지식에는 시점이 있어, 최신 버전과 다를 수 있습니다.
- **맥락을 모르는 결정**: 프로젝트 전체 사정을 모르고 일부만 보고 고치기도 합니다. → `AGENTS.md` 로 규칙을 적어 두면 줄어듭니다.
- **최종 책임은 사람**: 내 이름으로 들어가는 코드의 책임은 **나에게** 있습니다. 이해 못 한 코드는 그대로 쓰지 말고, **설명을 요청**해 이해한 뒤 받아들이세요.

> ⚠️ **검증의 황금률**: "동작하는 것처럼 보인다" ≠ "맞다". 직접 **실행**해 보고, 가능하면 **테스트**로 확인하고, 못 알아보는
> 코드는 **물어서 이해**한 다음 합치세요. Codex 가 만든 변경은 **git diff 로 읽고 커밋**하는 습관이 이 검증의 핵심입니다.

## 보안·저작권 유의 사항 🔒

- **비밀 정보 금지**: 비밀번호, API 키, 토큰, 개인정보를 프롬프트에 넣지 마세요. 필요하면 `YOUR_API_KEY` 같은 **자리표시자**로.
  (06 강좌의 `config.h`, `.env` 같은 파일은 에이전트가 읽지 않게 `.gitignore` 와 함께 관리)
- **비공개 코드**: 외부로 보내면 안 되는 코드는 팀의 **정책**을 먼저 확인하세요. 에이전트는 프로젝트 파일을 읽어 서버로 보냅니다.
- **라이선스·저작권**: AI 가 만든 코드가 특정 오픈소스와 비슷할 수 있습니다. 배포 전 **출처·라이선스**를 살펴보세요.
- **의존성 점검**: AI 가 추천한 라이브러리가 실제로 **유지보수되는 신뢰할 만한 것**인지 확인.
- **명령 실행 승인**: 에이전트가 파일 삭제·설치·git push 같은 명령을 실행하려 할 때는 **내용을 읽고** 승인하세요. ([02](02-getting-started-with-codex.md) 승인 모드)

> 💡 한 줄 원칙: **"외부에 나가면 곤란한 것은 입력하지 않는다. 되돌릴 수 없는 명령은 읽고 승인한다."**

## 정리

- 에이전트 코딩 = **자연어 요청 → 생성 → 검토·수정**의 반복.
- 잘 시키는 법 = **구체적 목표 · 맥락 · 작게 쪼개기 · 검증 · 피드백**.
- AI 는 빠른 도구일 뿐, **판단과 책임은 사람**. 검증을 건너뛰지 마세요.
- 도구는 **매우 빠르게** 바뀝니다. 늘 **`--help` 와 공식 문서**를 함께 보세요.
