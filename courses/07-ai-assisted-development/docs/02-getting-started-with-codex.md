# 02. Codex CLI 시작하기 🧭

## 한 줄 요약

> **Codex CLI** 는 OpenAI 가 만든 **터미널용 AI 코딩 에이전트**입니다. 프로젝트 폴더에서 `codex` 를 치면 대화창이 열리고,
> 자연어로 시키면 **파일을 읽고·고치고·명령을 실행**합니다. 사람은 **승인 모드**로 얼마나 자율적으로 움직일지 정하고,
> 결과(diff)를 검토합니다.

> ⚠️ Codex CLI 는 빠르게 바뀝니다. 명령·옵션·화면 문구가 아래와 다르면 **`codex --help`** 와 공식 문서를 기준으로 삼으세요.
> (이 문서는 `codex-cli 0.15x` 기준)

## Codex CLI 가 무엇인가요?

- **터미널에서 동작**: 별도 IDE 없이 PowerShell/터미널에서 실행. VS Code 안 터미널에서 쓰면 코드와 대화를 한 화면에.
- **에이전트**: 코드를 제안만 하는 게 아니라 **직접 파일을 수정하고, 테스트·빌드·git 명령을 실행**합니다.
- **샌드박스 + 승인**: 기본적으로 **현재 프로젝트 폴더 안에서만** 파일을 바꾸고, 그 밖의 위험한 동작은 **사람에게 승인**을 받습니다.
- **ChatGPT 계정으로 로그인** (00 강좌에서 완료). Windows · macOS 지원.

> 💡 쉽게 말해 **"터미널에 사는 코딩 조수"**. 여러분은 지시하고 결과를 검토하는 **팀장 역할**을 합니다.

## 0. 시작 순서 한눈에

```
1) 설치·로그인 확인 (00 강좌에서 완료)
2) 프로젝트 폴더로 이동 (cd) — 에이전트는 "지금 폴더"를 작업 공간으로 본다
3) codex 실행 → 대화창
4) 자연어로 요청 → 에이전트가 파일 수정/명령 실행 → 변경 검토 → 승인/피드백 → 반복
5) 만족하면 git 으로 커밋 (검토의 마무리)
```

## 1. 설치·로그인 확인

```bash
codex --version          # codex-cli 0.x.x
codex login status       # 로그인 상태
```

로그인이 안 되어 있으면 `codex login` (브라우저가 열림 → ChatGPT 계정). 문제가 있으면 `codex doctor` 가 설치·설정·인증 상태를 진단해 줍니다.

> 💡 업데이트: `codex update` (또는 Windows `winget upgrade OpenAI.Codex`, macOS `brew upgrade codex`)

## 2. 실행 — 프로젝트 폴더에서

에이전트는 **`codex` 를 실행한 폴더**를 작업 공간(workspace)으로 봅니다. 그 안의 파일을 읽고 고칩니다. 그래서 **먼저 `cd`**.

```bash
mkdir led-panel-codex
cd led-panel-codex
codex                          # 대화형 화면(TUI) 시작
```

첫 실행 시 안내 문구·모델 선택이 나올 수 있습니다. 기본값으로 진행하면 됩니다.

```bash
codex "이 폴더에 순수 HTML/CSS/JS 로 LED 제어판 index.html 을 만들어줘"   # 첫 요청을 인자로 바로 시작
```

> ⚠️ 저장소 최상위나 홈 폴더(`~`)에서 실행하지 마세요. 에이전트가 볼 파일이 너무 많아지고, 엉뚱한 곳을 고칠 수 있습니다.
> **실습용 빈 폴더**나 **작업할 프로젝트 폴더**에서만.

## 3. 화면 구성

```
┌──────────────────────────────────────────────────────┐
│  (대화 기록)                                          │
│  › 사용자: LED 제어판 만들어줘                          │
│  • 에이전트: index.html 을 만들었습니다 …               │
│    ✎ index.html (+42)   ✎ style.css (+30)             │  ← 바뀐 파일
│    $ python -m http.server 8000   [승인 요청]           │  ← 명령 실행 승인
├──────────────────────────────────────────────────────┤
│  › 여기에 입력                                         │  ← 입력창
│  model · approval: … · workspace: ~/led-panel-codex    │  ← 상태 표시줄
└──────────────────────────────────────────────────────┘
```

- **입력창**에 자연어로 요청. Enter 로 전송, `Shift+Enter`(또는 `\` 뒤 Enter)로 줄바꿈.
- 에이전트가 **어떤 파일을 어떻게 바꿨는지** 요약과 diff 를 보여 줍니다.
- **명령을 실행**하려 할 때 승인 모드에 따라 **[y/n] 승인 요청**이 뜹니다.
- 나가기: `/quit` 또는 `Ctrl + C` 두 번.

## 4. 승인 모드와 샌드박스 — 얼마나 맡길까

Codex 는 두 축으로 안전장치를 둡니다.

| 축 | 값 | 의미 |
|----|----|------|
| **샌드박스** (`-s`) | `read-only` | 파일 읽기만. 수정·실행 불가 (코드 설명·리뷰용) |
| | `workspace-write` (기본) | **현재 폴더 안**만 수정 가능. 그 밖과 네트워크는 승인 필요 |
| | `danger-full-access` | 제한 없음 — **쓰지 마세요** |
| **승인** (`-a`) | `on-request` (기본) | 에이전트가 필요할 때 승인을 물음 |
| | `never` | 묻지 않음 (자동화용) |

대화 중에는 **`/approvals`** 로 프리셋을 바꿀 수 있습니다. (버전에 따라 **Read Only / Auto / Full Access** 같은 이름)

```bash
codex -s read-only            # 코드만 읽고 설명·리뷰하게 (안전하게 시작하기 좋음)
codex                         # 기본: 폴더 안 수정 OK, 위험한 건 물어봄  ← 실습 기본
```

> ⚠️ 승인 요청이 뜨면 **명령을 읽으세요.** `rm -rf`, `git push --force`, 패키지 전역 설치처럼 되돌리기 어려운 것은 특히.
> 승인 권한은 사람에게 있습니다. 모르면 `n` 을 누르고 "이 명령이 왜 필요한지 설명해줘" 라고 물으세요.

## 5. 대화 중 슬래시 명령

| 명령 | 하는 일 |
|------|---------|
| `/init` | 프로젝트 설명 파일 **`AGENTS.md`** 초안 생성 ([03](03-working-with-codex.md)) |
| `/model` | 모델 바꾸기 |
| `/approvals` | 승인·샌드박스 프리셋 바꾸기 |
| `/diff` | 지금까지 바뀐 내용(git diff) 보기 |
| `/status` | 현재 모델·모드·사용량 |
| `/review` | 현재 변경에 대해 코드 리뷰 요청 |
| `/new` | 새 대화 시작 (맥락 초기화) |
| `/compact` | 긴 대화를 요약해 맥락 줄이기 |
| `/quit` | 종료 |

> 💡 `/` 만 치면 목록이 뜹니다. 정확한 이름은 버전마다 다를 수 있으니 목록을 보세요.

## 6. 첫 요청 — 만들기 → 확인 → 다듬기

처음 감을 잡기 좋은, 작고 안전한 요청들입니다. (실습 01 에서 단계별로 진행)

```
1) "순수 HTML/CSS/JS 로 'LED 제어판' 웹 페이지를 만들어줘 (index.html, style.css, script.js).
    이름 입력칸, '켜기'/'끄기' 버튼, 동그란 표시등, 변경 이력 목록이 있어. 포인트 색은 보라색(#6b4e9e)."

2) (만들어지면) "index.html 을 브라우저에서 열어 볼 수 있게 간단한 로컬 서버를 띄워줘"
    → 명령 실행 승인 요청이 뜸 → 읽고 승인 → 브라우저로 확인

3) "켜기를 누르면 표시등을 노란색, 끄기를 누르면 회색으로 바꾸고,
    누를 때마다 '[시각] 이름 님이 LED를 켰/껐습니다' 를 목록 맨 위에 추가해줘. 이름이 비면 '익명'."
```

→ **만들기 → 실행 확인 → 다듬기**의 반복을 그대로 체험합니다.

## 7. 유용한 실행 옵션

```bash
codex -i screenshot.png "이 화면처럼 만들어줘"     # 이미지 첨부 (디자인 시안·에러 스크린샷)
codex -C ~/projects/led-server "..."               # 다른 폴더를 작업 공간으로
codex --search "FastAPI 최신 버전의 WebSocket 예제를 찾아 적용해줘"   # 웹 검색 허용
codex resume --last                                # 직전 대화 이어서
codex exec "README 의 오타를 고쳐줘"               # 대화 없이 한 번 실행하고 종료 (자동화·스크립트용)
codex review                                       # 현재 저장소 변경 사항 코드 리뷰
```

## 자주 막히는 문제

| 증상 | 해결 |
|------|------|
| `codex: command not found` | 00 강좌 설치 확인, **터미널 새로 열기** |
| 로그인 브라우저가 안 열림 | 터미널에 출력된 URL 을 복사해 직접 열기 |
| 에이전트가 파일을 못 찾음 | `codex` 를 **프로젝트 폴더에서** 실행했는지 (`pwd`) |
| "권한/샌드박스" 오류로 명령 실패 | 폴더 밖을 건드리려 한 것. 필요하면 `--add-dir` 또는 프로젝트 안으로 옮기기 |
| 결과가 엉뚱함 | 요청이 모호했을 확률 ↑ → 맥락·목표를 구체적으로 ([01](01-what-is-ai-development.md)), `AGENTS.md` ([03](03-working-with-codex.md)) |
| 화면·명령이 자료와 다름 | 정상 — **버전 차이**. `codex --help`, `/` 목록, 공식 문서 |

## 정리

- Codex CLI = **터미널의 코딩 에이전트**. **프로젝트 폴더에서** `codex`.
- 안전장치 = **샌드박스**(폴더 안만) + **승인**(위험한 건 물어봄). 승인 요청은 **읽고** 결정.
- 흐름 = **요청 → 변경 검토 → 실행 확인 → 피드백** 반복. 만족하면 **git 커밋**.
- `/init` `/diff` `/review` `/approvals` — 자주 쓰는 슬래시 명령.
